Cloud einrichten

Die Bilder kommen aus einer Nextcloud. Der Raspberry Pi holt sie selbst ab, sobald er im Netz ist (WLAN, Hotspot, gleich welches). Auf dem Pi läuft dafür kein Dienst, der von außen erreichbar wäre. Wer Bilder beisteuert, braucht weder ein Konto noch eine App, nur einen Link.

Wer macht was?

WerZugangDarf
Betreibereigenes Nextcloud-Konto, Quellcode, ssh zum Pialles: Ordner, Links, config.yaml, Passwort auf dem Pi
Raspberry PiKonto diashow mit App-Passwortden Bilderordner lesen (am besten nur lesen)
BildlieferantenUpload-Link + Link-Passwortnur Bilder hinzufügen; nichts sehen, ändern oder löschen

1. Konto und Ordner anlegen

Der Pi bekommt ein eigenes Konto, z. B. diashow, nicht das persönliche Konto des Betreibers. Geht der Pi verloren, ist nur dieses Konto betroffen.

Variante A, einfach: Als diashow anmelden und einen Ordner bilder anlegen. Mit dem Passwort des Pi ließen sich dann aber auch Bilder in der Cloud löschen (der Pi selbst tut das nie).

Variante B, empfohlen: Der Ordner gehört dem Konto des Betreibers, z. B. Diashow. Er wird mit dem Benutzer diashow nur lesend geteilt (Teilen → Benutzer diashow → Berechtigung „Nur lesen“). Beim Konto diashow erscheint er als Ordner Diashow. Ein gestohlenes Pi-Passwort kann so nichts zerstören.

Nur .jpg/.jpeg-Dateien direkt in diesem Ordner kommen auf den Stick; Unterordner und andere Dateien werden ignoriert.

2. App-Passwort für den Pi

Der Pi meldet sich nicht mit dem normalen Passwort an, sondern mit einem App-Passwort, das sich jederzeit einzeln widerrufen lässt:

  1. Als diashow anmelden.
  2. Persönliche Einstellungen → Sicherheit → Geräte & Sitzungen.
  3. App-Name eingeben, z. B. raspberry-pi, dann Neues App-Passwort erstellen.
  4. Das angezeigte Passwort (Form xxxxx-xxxxx-xxxxx-xxxxx-xxxxx) gleich in Schritt 4 verwenden. Es wird nur einmal angezeigt.
Das App-Passwort nie per Mail, Chat, Issue oder Foto weitergeben und nicht in config.yaml schreiben. Ist es doch einmal herausgegeben worden: in derselben Liste löschen und ein neues erstellen.

3. Adresse und Ordner in config.yaml

Öffentliche Adresse der Nextcloud, Konto und Ordner kommen in den Abschnitt cloud: der config.yaml auf dem Stick: 

cloud:
  address: https://cloud.example.org   # die Adresse, die auch im Browser steht
  user: diashow
  folder: Diashow                      # Variante A: bilder
sequence:
  - slideshow

Daraus wird die WebDAV-Adresse https://cloud.example.org/remote.php/dav/files/diashow/. Ein Wechsel des Ordners oder Servers wirkt beim nächsten Abgleich. Dazu einfach die Datei auf dem Stick ändern, ein Neustart ist nicht nötig.

4. Passwort auf dem Pi hinterlegen

Einmal, vom Rechner mit dem Quellcode aus:

make diashow-setup

Das öffnet eine ssh-Sitzung zum Pi und fragt nach dem App-Passwort; die Eingabe ist unsichtbar. Adresse und Konto nimmt es aus cloud: in der config.yaml. Fehlt der Abschnitt, fragt es einmal danach. Das Passwort wird verschleiert in ~/.config/rclone/rclone.conf auf der SD-Karte des Pi gespeichert (nur für den Benutzer lesbar). Danach wird die Anmeldung gleich getestet und der stündliche Abgleich eingeschaltet: 

App password for Nextcloud user diashow:
remote nc: saved in /home/…/.config/rclone/rclone.conf
remote nc: ok
diashow-sync.timer enabled

Neues Passwort (z. B. nach Widerruf): neues App-Passwort erstellen, make diashow-setup noch einmal ausführen.

5. Der Abgleich

  • Wann: 2 Minuten nach dem Einschalten, dann stündlich. Sofort: make diashow-sync.
  • Was: Der Ordner auf dem Stick (/mnt/stick/bilder) wird eine genaue Kopie des Cloud-Ordners: Neue Bilder kommen dazu, in der Cloud gelöschte verschwinden. Andere Dateien auf dem Stick bleiben unberührt.
  • Die Show liest den Ordner jede Runde neu; neue Bilder erscheinen ohne Neustart.
  • Offline: Der Abgleich bricht ab, bevor er etwas ändert; der nächste versucht es wieder.
  • Ohne Stick: Es wird nichts getan, damit nichts auf der SD-Karte landet.
  • Löschschutz: Würde ein Abgleich mehr als 20 Bilder löschen (z. B. weil der Ordner geleert oder die Freigabe entfernt wurde), bricht er ab, ohne etwas zu ändern.

make status zeigt das Ergebnis des letzten Abgleichs:

picture sync: sync ok: 61 pictures (2 new, 0 deleted) (next: …)
Ordner gewechselt? Dann sähe der Abgleich viele Bilder als „gelöscht“ und der Löschschutz greift. Einmalig erlauben: 
ssh <pi> 'DIASHOW_MAX_DELETE=1000 ~/fb-slideshow/ci/diashow-sync.sh'

6. Bildlieferanten einrichten

Wer Bilder beisteuert, bekommt einen Upload-Link („Dateiablage“, englisch File drop) mit eigenem Passwort. Damit kann man im Browser des Handys Bilder hochladen, aber nichts sehen, ändern oder löschen. Ein App-Passwort dafür herauszugeben wäre falsch: Es öffnet das ganze Konto.

  1. Als Eigentümer des Ordners anmelden (Variante A: diashow, Variante B: der Betreiber), den Ordner öffnen, Teilen.
  2. Link teilen → + (neuen Freigabelink erstellen).
  3. In den Einstellungen des Links (⋯):
    • Berechtigung „Dateiablage (nur Hochladen)“ (File drop)
    • Passwort festlegen, ein eigenes, nur für das Hochladen
    • Ablaufdatum nach Wunsch
    • Speichern
  4. Link kopieren. Mit ⋯ → QR-Code anzeigen gibt es ihn auch als QR-Code, den jede Handykamera liest.
  5. Den Lieferanten Link und Passwort geben, am besten auf getrennten Wegen, dazu die Anleitung Bilder hochladen.
AufgabeSo geht's
Passwort ändernin den Einstellungen desselben Links; der Link bleibt gleich
allen den Zugang sperrenden Link löschen
mehrere Gruppenmehrere Links mit je eigenem Passwort, einzeln widerrufbar
unerwünschtes Bildals Eigentümer in der Cloud löschen; der nächste Abgleich entfernt es vom Stick

Falsche Passwörter bremst Nextcloud automatisch aus (Brute-Force-Schutz). Hochgeladene Bilder erscheinen ohne Prüfung spätestens nach einer Stunde auf dem Display.
