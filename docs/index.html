fb-slideshow – Dokumentation

Hinweis: Die Software wird ohne Gewähr angeboten. Quellcode: github.com/fritzthekid/fb-slideshow

Worum es geht

Ein Raspberry Pi mit einem kleinen 3,5-Zoll-Display (480×320 Pixel) zeigt als digitaler Bilderrahmen Fotos, mit sanften Übergängen, einer kleinen Uhr und gelegentlich einer Szene: Ein Text fliegt von klein nach groß in die Bildmitte und zerfällt dort in Funken.

Alles, was gezeigt wird, steht in einer einzigen Datei: config.yaml auf dem USB-Stick. Die Bilder kommen aus einer Cloud (Nextcloud), in die mehrere Personen Fotos hochladen können, ohne Zugang zum Gerät zu haben.

Wie die Teile zusammenspielen

  Bildlieferanten                Cloud (Nextcloud)               Raspberry Pi
  (Handy, Browser)  ──Upload──▶  Ordner "bilder"   ──stündlich──▶  USB-Stick /mnt/stick
                    Upload-Link                     rclone         ├── config.yaml
                    + Passwort                                     └── bilder/*.jpg
                                                                        │
                                                                        ▼
                                                                   Display 480×320
  • USB-Stick (/mnt/stick): enthält config.yaml und den Ordner bilder/. Änderungen an config.yaml wirken ohne Neustart, spätestens nach dem aktuellen Bild.
  • Cloud: Adresse, Benutzer und Ordner stehen im Abschnitt cloud: der config.yaml. Das Passwort liegt nur auf der SD-Karte des Raspberry Pi, nie auf dem Stick. Siehe Cloud einrichten.
  • Abgleich (mit pull: true in cloud:): Zwei Minuten nach dem Einschalten und danach stündlich holt der Pi neue Bilder aus der Cloud auf den Stick. Bilder, die in der Cloud gelöscht wurden, verschwinden auch vom Stick.
  • Bildlieferanten bekommen nur einen Upload-Link mit eigenem Passwort. Sie können Bilder hinzufügen, aber nichts sehen oder löschen. Anleitung für sie: Bilder hochladen.

Erste Schritte

  1. Eine config.yaml schreiben, am einfachsten ausgehend von einem der Beispiele, und auf den Stick kopieren (/mnt/stick/config.yaml). Ohne diese Datei zeigt das Gerät einfach alle Bilder nacheinander.
  2. Die Cloud eintragen: Abschnitt cloud: mit Adresse, Benutzer und Ordner, dann einmal das App-Passwort auf dem Pi hinterlegen (make diashow-setup), siehe Cloud einrichten.
  3. Upload-Link anlegen und an die Bildlieferanten weitergeben.
  4. Prüfen: make start meldet einen Fehler in der Datei sofort, make status zeigt, was gerade läuft.

Befehle

Die Befehle laufen auf dem Rechner mit dem Quellcode und sprechen den Pi per ssh an (Einzelheiten im README).

BefehlWirkung
make start / make restartDiashow starten bzw. neu starten; meldet eine fehlerhafte config.yaml
make stop, make pause, make resumeanhalten, pausieren, weiter
make statusläuft sie? welche Sequenz? letzter Cloud-Abgleich
make sequencelokale config.yaml prüfen und auf den Stick kopieren
make moviedie Sequenz als Film rendern, um sie vorher anzusehen
make diashow-setupApp-Passwort der Cloud auf dem Pi hinterlegen (nur auf der SD-Karte)
make diashow-syncBilder jetzt aus der Cloud holen
make show-setup USERS="richard"weiteren Benutzern auf dem Pi den Befehl show geben (siehe unten)

Direkt am Pi: show

Auf dem Pi selbst geht dasselbe ohne den Rechner mit dem Quellcode: show status, show start, show stop, show restart, show pause, show resume, show diashow-sync.

Wer show benutzen darf, ist Mitglied der Gruppe slideshow. Eingerichtet wird das einmal mit make show-setup USERS="richard"; weitere Benutzer kommen mit sudo usermod -aG slideshow <name> dazu und können show nach dem nächsten Anmelden benutzen. Mehr als die Diashow steuern können sie damit nicht.
